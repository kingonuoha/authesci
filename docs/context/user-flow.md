Role 1: The Unauthenticated Visitor
Start: Lands on Homepage.
Exploration: Views Hero section. Sees three feature areas (Marketplace, Project Workspace, In-Lab).
Simplification: Feature Card for In-Lab Mode shows 'Coming Soon'. Marketplace and Project Workspace CTAs lead to the Sign Up/Login page to encourage registration.
Action: Clicks "Get Started" or "Sign Up Now".
Authentication Flow:
Path A (New User): Sign Up Form Enter Name, Email, Password, Institution, Role (Scientist/Employer) → Clicks "Create Account".
Path B (Existing User): Login Page → Enter Email/Password → Clicks "Sign In".
End: Redirected to respective Role Dashboard (Scientist Dashboard or Employer Dashboard).
Role 2: The Scientist (Core User)
1. Start: Login & Dashboard
·       Entry Point: User logs into the platform.
2. Profile Setup (Required)
 Action: User navigates to My Profile.
Inputs: User manually fills in the following fields:
o   Professional Summary
o   Work Experience
o   Skills
o   Publications
o   Uploads: CV/Resume and Certifications
AI Functionality: Once the profile is complete, the system uses AI to suggest relevant job postings based on the user’s skills and experience.
3. Flow A: Job Seeking (Job Marketplace)
3.1 Navigation
Action: User navigates to Job Marketplace.
Filter Options: Search by keyword, Remote/Hybrid/On-site, and area of specialization.
3.2 Application Process
Action: User selects a job listing → Views job details → Clicks Apply Now.
Form: Application form opens with:
o   Pre-filled personal and profile details
o   Text field for cover letter entry
o   Option to upload CV or portfolio
o   Confirmation checkbox for data sharing
o   Employer-specific questions (if any)
3.3 Submission
Action: User clicks Submit Application.
Outcome:
o   Success confirmation message displayed. Also, email confirmation.
o   Application automatically tracked in Dashboard under My Applications with status indicators: Submitted, Under Review, and Rejected.
Flow B: Project Collaboration (Project Workspace)
4.1 Navigation
Action: The scientist navigates to the Project Workspace.
Options: View existing projects, or Click “+ Create New Project” to start a new one.
4.2 Inside a Project
a. Manage Documents
Uploads project-related files such as protocols, datasets, or results.
Files are displayed in a simple, flat list view (no nested folders).
Each file includes metadata such as file name, upload date, and uploader identity.
b. Manage Tasks
Creates and assigns tasks to self or collaborators.
Sets due dates and tracks progress.
Task statuses include:
Open — task pending or in progress.
Complete — task successfully finished.
Tasks are displayed in a Kanban board-style interface for easy visualization of workflow.
c. Invite Collaborators
User can invite collaborators by:
Sharing a secure project link with other registered Scientists or Employers, or
Manually entering collaborator email addresses (registered users only).
Invited collaborators gain restricted access to the project workspace with defined permissions (e.g., view, upload, or edit).
4.3 Collaboration Outcome
Collaborators can upload documents, manage assigned tasks, and contribute updates in real time.
All activities are logged within the project for transparency and version tracking.
Role 3: The Employer (Job Posting & Hiring)
1. Start: Login & Dashboard
Entry Point: Employer logs in to their account.
Landing Page: Employer Dashboard — displays key stats such as:
Active job postings
Number of applicants
Application statuses (New, Under Review, Shortlisted, Rejected)
2. Flow A: Posting a Job
2.1. Action: Create Job Post
User clicks “+ Post New Job”.
Job Posting Form opens, requiring inputs such as:
Job Title
Job Description
Location
Salary Range
Employment Type
Once filled, the job appears on the dashboard as Draft status.
2.2 Review & Publish
Employer reviews entered details.
Clicks “Publish Job” to proceed.
2.3 Payment Option (Monetization Layer)
Posting is free by default.
However, it is clearly stated that paid (sponsored) jobs gain higher visibility and priority placement in search results.
Employer is given the choice to promote the job post for a flat fee (e.g., $5).
2.4 Payment Flow (If Opted):
If the employer chooses to pay:
Redirected to Payment Page.
Payment details and fee summary are displayed.
User enters payment information and confirms.
Upon successful payment confirmation:
Job becomes visible to scientists in the Job Marketplace.
3. Flow B: Reviewing Applications
3.1 Action: Access Applications
Employer navigates to the “Applications” tab.
Views a list of candidates who have applied for their job posting.
3.2 Review Process
Clicks on a candidate to view:
Submitted CV/Resume
Cover Letter
Basic Profile Summary (Experience, Skills, Certifications)
3.3 Decision Options
From the candidate view, the employer can take one of the following actions:
Shortlist — marks the candidate for further consideration.
Reject — removes candidate from shortlist and updates status.
Contact — sends a direct message or email through the platform.
3.4 Communication & Interview
When the employer chooses Contact, a built-in chat and video interview interface opens within the platform.
This enables direct communication and live interviews between employers and scientists.
All interactions remain within the Authesci platform.
3.5 Escrow-Based Project Agreement
If the employer decides to move forward with a candidate and both parties agree on a fixed project fee (e.g., $20):
Employer initiates a “Hire & Fund Project” action.
Payment is securely held in Authesci’s escrow system.
Scientist begins work on the project through the Project Workspace.
Upon project completion, both parties confirm satisfaction through the platform.
Authesci releases the funds to the scientist.
Role 4: The Invited Collaborator (Project Workspace - Simplified MVP)
Start: Receives invitation link to a Project Workspace.
Authentication: Is prompted to Log In or Sign Up if they don't have an account.
Access: Upon authentication, they are granted restricted access to the specific Project Workspace.
Contribution: They can only see and interact with the elements (simple tasks, documents) permitted by the project owner.
End: Contributes to the project as needed.
